# 真实 API 多轮与并发验收 · 2026-11-05

按用户授权增加真实调用强度，在 `e43a85e` 上新增 **440 次真实 API 请求**：MiMo 50 轮 / 200 次，中转站 50 轮 / 200 次，OpenAI Luna 10 轮 / 40 次。每轮含普通、流式的直连和 Selark 中转各一次。测试于北京时间 14:15:26–14:27:55 完成，共 749 秒；本报告不包含上一轮的 12 次调用。

本轮没有传输/协议错误、超时或重复派发；**220 条中转记录全部保存，恢复积压为 0**。中转站出现 6 次空回复和 5 次输入 Token 报告明显偏高，不能把协议正常结束等同于有效回答。

## 范围与方法

- MiMo 请求 `mimo-v2.6-flash`，中转站请求 `claude-sonnet-4-6`，OpenAI 只请求 `gpt-6-luna`。输出上限分别为 16、16、64，输入固定为 `Reply with exactly OK.`。
- MiMo、中转站前 20 轮为顺序对照，后 30 轮为最高 4 并发；Luna 的 10 轮全部为顺序测试。交替直连/中转与普通/流式顺序，轮换供应商顺序；并发阶段每批至多 4 个请求，实测核心活跃请求峰值为 4。
- 所有真实请求都发往已有配置中对应的 API。真实密钥只保留在内存，使用临时调用方、临时数据库和隔离服务；没有修改日常配置或重启用户服务。
- 每个样本最多一次派发，失败不补发，不切换模型，不将坏样本替换成成功样本。逐个检查方法、目标、凭据、模型、完整负载、输出上限与次数上限；本机样本标识和会话 ID 不进入上游消息。
- 直连与中转使用同一供应商适配器及上游 HTTP 客户端，继承相同外部代理环境；本机客户端忽略系统代理。每个“连接 × 流模式”的全部出站 JSON 哈希保持一致，共 6 个固定哈希，包含直连和中转。
- 普通延迟测至完整响应，SSE 首段延迟只统计真实非空文本；空回复首段时间为 `null`，不计作 0 ms。流完成时间另存。结束原因、文本片段、报告用量与失败样本均保留。

测试器和临时核心在同一进程，启用了开发探针和测试进度写盘；为了不复制密钥，连接快照在内存中，未复制用户的历史账本。这是带观测开销的短文本真实 API 验收，不是生产环境的 10 ms 本机开销预算测试，也不覆盖长上下文、大输出或更高并发。直连/中转分别产生一次真实生成，受网络、缓存和上游调度影响，不能用二者总耗时相减来认定 Selark 的额外延迟。

## 已复现的异常

### 中转站空回复

6 次都发生在并发 SSE 阶段：直连 2 次、中转 4 次。均收到正常终止标志及 `finish_reason=stop`，供应商报告 15 个输入、0 个输出 Token，但没有文本。

| 样本 | 路径 |
| --- | --- |
| `r21.relay-personal.1.relay` | Selark |
| `r21.relay-personal.1.direct` | 直连 |
| `r31.relay-personal.1.relay` | Selark |
| `r32.relay-personal.1.direct` | 直连 |
| `r39.relay-personal.1.relay` | Selark |
| `r48.relay-personal.1.relay` | Selark |

这是本轮中转站全部请求的 3%，并发 SSE 请求的 10%。直连也复现，出站负载一致；现有证据不能把问题只归因于 Selark。普通响应与其他两个 API 未出现空回复。空回复对应的中转账本仍保留供应商报告值，没有自动补答。

### 中转站输入 Token 报告跳变

相同短输入通常报告 12 个输入 Token，但 5 次普通响应报告 **1,968–2,901** 个输入 Token：

| 样本 | 路径 | 报告输入 Token | 已报告缓存信息 |
| --- | --- | ---: | --- |
| `r19.relay-personal.0.direct` | 直连 | 2,029 | cached 1,476；cache write 553 |
| `r21.relay-personal.0.relay` | Selark | 1,968 | cached 1,968 |
| `r22.relay-personal.0.relay` | Selark | 1,968 | cached 1,968 |
| `r22.relay-personal.0.direct` | 直连 | 1,968 | cached 1,968 |
| `r39.relay-personal.0.relay` | Selark | 2,901 | cached 2,152；cache write 749 |

这些样本均返回 `OK.`，输出计数为 1；其余常规非空中转站样本报告输入 12、输出 5。完整负载哈希一致，且跳变同时出现在直连和中转中，不能据此认定 Selark 添加了提示或调用。实际原因可能涉及第三方路径、适配或计量差异，尚未确认；不据此断言隐藏提示、模型替换或账单错误，也不擅自修正供应商数字。MiMo 的全部输入计数为 14，Luna 的全部输入计数为 11。

### 本机交付尾延迟

探针单独记录“供应商适配器交出结果/首段文本 → 本机客户端收到”的间隔。顺序阶段出现约 **40–64 ms** 的尾部样本，对应检查点多为约 5 ms，部分时间位于 ASGI 正文送出时点至客户端观察之间；不能全部归因于数据库。

4 并发阶段，MiMo/中转站非空 SSE 的此间隔中位数分别约 0.52 / 0.51 ms，样本 p95 约 0.81 / 0.86 ms；普通响应中位数约 5.88 / 6.17 ms。这只是交付末段，排除了派发前处理和上游生成，不能当作完整中转额外延迟。

测量器与核心共享事件循环，存在探针和报告写盘开销。上述顺序阶段尾延迟的原因尚未确定，后续应分进程复现并检查连接状态/客户端接收，不将它宣称为已修复或稳定的生产指标。
