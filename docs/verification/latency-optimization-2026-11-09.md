# 连接复用与持久化延迟优化 · 2026-11-09

本轮减少了 SSE 的连接重建和健康请求的重复工作。同环境三轮独立测量中，SSE 首段额外延迟 p95 的中位数从 **12.6550 ms 降至 8.6525 ms（约 31.6%）**；普通响应 p95 仅从 18.0181 ms 变为 17.6818 ms，不能认定其尾延迟稳定改善。**10 ms 预算尚未稳定达成**，阈值保持不变。

完整逐对样本、每轮预算判定、源码和测量脚本摘要及安装验收结果保存在 [JSON 证据](latency-optimization-2026-11-09.json)。全部请求来自临时合成配置和回环模拟上游，真实供应商调用为 0；没有读取个人配置或替换日常运行的服务。

## 改动与正确性边界

- **完成的 SSE 连接复用**：Chat、Anthropic 和原生 Responses / Messages 在交付合法终态后，尝试读完 HTTP 响应尾部以归还连接池。每次最多读取 64 行，累计超过 64 KiB 即停止，单行仍受既有解析器大小限制；读取等待上限 10 ms，停滞或超限时关闭连接。已经开始的 HTTPX 关闭仍允许在既有 2 秒上限内完成，避免取消发生在 `is_closed` 标记与传输层释放之间。终态后的读取错误不改写已交付结果或已知用量，外部取消仍传播。
- **减少一次路由读取**：立即获得执行名额的请求复用刚取得的路由结果；排队后重新读取。派发前仍在管理锁内复查模型审批与连接指纹，并在 SQLite 事务内检查当前令牌、应用权限、并发和配额。没有跨请求的授权缓存。
- **减少最终收据重写**：交付前仍先写恢复收据并同步文件/目录，再提交 SQLite 检查点，确保独立 CLI 在交付终态前就能看到真实用量。交付后的最终结算先执行 SQLite FULL 提交，成功后删除旧收据；提交失败才写入携带实际交付状态的最终收据。旧收据清理失败会阻止新准入并触发恢复；在线与重启恢复均按修订号防止旧检查点覆盖已结算状态。

没有新增常驻进程、线程、授权缓存或空闲轮询。SSE 尾部读取仅创建一个短暂任务并在清理中回收。生成派发次数、调用方文本、未知用量和推理用量语义不变；SQLite 同步等级、文件/目录同步及持久恢复检查点均保留。

## 环境与方法

- Linux x86_64 / WSL2，内核 `5.15.167.4-microsoft-standard-WSL2`，Python 3.12.2；同一机器、解释器与锁定依赖，Dashboard 关闭，单请求并发。每批使用新核心进程和独立临时账本。
- 基线提交 `ca0153b048e8545a1c553674ebf03962f98cf6ee`；候选是本报告对应的修改。分别使用独立虚拟环境指向各自源码，避免子进程清理 `PYTHONPATH` 后误用同一版本。
- 两边使用完全相同的测量脚本，新增连接计数及 chunked SSE 选项；正式比较不开启开发探针。测量期间冻结运行时代码并校验摘要。
- 默认 Content-Length 分帧，顺序为 **基线 1、候选 1、候选 2、基线 2、基线 3、候选 3**。每批普通与 SSE 各 300 对样本、各 5 对预热，之后连续测量 30 秒核心空闲状态。
- 每对交替直连/中转次序，计算带符号的「中转 − 直连」差值，保留负值，使用 nearest-rank 百分位。下面汇总取三次独立百分位的中位数，**不合并成一个 p95，也不相减两个独立 p95**。
- 普通请求测到完整响应接收；SSE 首段测到第一段真实文本，流完成另报。RSS/CPU 仅统计核心 PID。回环代理绕行在两个版本中均显式关闭，不能将代理设置差额算作优化收益。

## 三轮结果与预算

下表单位为 ms，每格为「修改前 → 修改后」，均是三次独立百分位的中位数：

| 额外延迟 | p50 | p95 | p99 |
| --- | ---: | ---: | ---: |
| 普通完整响应 | 12.8179 → 10.9755 | 18.0181 → 17.6818 | 21.1948 → 20.3673 |
| SSE 首段文本 | 8.0431 → 5.1332 | 12.6550 → 8.6525 | 17.4453 → 11.0365 |
| SSE 流完成 | 13.8191 → 10.3489 | 19.4283 → 15.6317 | 23.3763 → 18.7393 |

逐轮 p95 如下，以免汇总隐藏未达标样本：

| 轮次 | 普通完整响应 | SSE 首段文本 | SSE 流完成 |
| --- | ---: | ---: | ---: |
| 基线 1 | 17.9205 | 14.5937 | 21.8005 |
| 候选 1 | 18.7944 | 10.1920 | 18.3642 |
| 候选 2 | 17.6818 | 8.6525 | 15.6317 |
| 基线 2 | 18.5858 | 11.1019 | 17.5373 |
| 基线 3 | 18.0181 | 12.6550 | 19.4283 |
| 候选 3 | 16.5616 | 7.8507 | 14.2729 |

| 预算项目 | 目标 | 基线中位数 / 达标轮次 | 候选中位数 / 达标轮次 |
| --- | ---: | ---: | ---: |
| 普通额外延迟 p95 | ≤ 10 ms | 18.0181 ms / 0 of 3 | 17.6818 ms / 0 of 3 |
| SSE 首段额外延迟 p95 | ≤ 10 ms | 12.6550 ms / 0 of 3 | 8.6525 ms / 2 of 3 |
| 核心空闲 RSS | ≤ 72 MiB | 59.83 MiB / 3 of 3 | 59.70 MiB / 3 of 3 |
| 核心空闲 CPU | ≤ 0.5% 单核 | 0.10% / 3 of 3 | 0.13% / 3 of 3 |

普通请求 p50 降低约 14.4%，但 p95 中位数仅降低约 1.9%，且第一轮变慢，变化可能受调度与持久化抖动影响，不能宣传为尾延迟稳定改善。SSE 首段 p95 在本组三轮中均降低，流完成 p95 中位数降低约 19.5%；不代表任意机器、并发、长文或真实供应商都具有同等收益。空闲 CPU 没有改善，只是保持在预算内。

六批各发生 610 次直连模拟生成和 610 次中转模拟生成；每批中转记入 8540 tokens，额外生成 0 次、空闲生成 0 次，完整上游载荷保持一致。每批普通阶段新增上游 TCP 连接均为 2（直连和中转各一条）；SSE 阶段基线新建 304 条，候选新建 0 条，复用已建立的连接。计数包含预热。全部严格预算命令都因普通延迟未达标而返回 1，报告完整保留。

## chunked SSE 补充对照

同环境、相同源码，各运行一次 300 对/模式、30 秒空闲批次，流式响应改用 HTTP chunked 分帧：

| 额外延迟 p95 | 基线 | 候选 |
| --- | ---: | ---: |
| 普通完整响应 | 18.4658 ms | 16.3446 ms |
| SSE 首段文本 | 14.1056 ms | 9.1583 ms |
| SSE 流完成 | 21.2519 ms | 15.9157 ms |

SSE 阶段新增连接仍为 304 → 0，说明本次连接复用不依赖 Content-Length 分帧。两边的 RSS/CPU 均通过预算，普通延迟仍未通过。这是单独的一组补测，不纳入三轮中位数，也不能据此断言 chunked 下已经稳定达到 10 ms。
