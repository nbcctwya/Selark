# 资源占用与转发边界验收 · 2026-11-04

基线为 Selark `4cec838`；前端优化为 Selark-Web `fb4cecc`。在本机 Linux / WSL、Python 3.12.2、相同依赖下比较；各样本使用新进程、独立临时配置和模拟上游，无真实模型请求或个人配置修改。

## 测量

每组各运行三次，以下为中位数。详细样本与后端改动文件 SHA-256 见 [测量数据](efficiency-measurements-2026-11-04.json)。

| 指标 | 改动前 | 改动后 |
| --- | ---: | ---: |
| 实际 `selark serve` 进程空闲 RSS | 65.89 MiB | 57.99 MiB |
| 进程内测量的空闲 RSS（含模拟调用方） | 60.68 MiB | 54.36 MiB |
| 空闲 10 秒的恢复目录扫描次数 | 20 | 0 |
| 进程内测量的空闲 CPU 时间 | 0.006913 秒 | 0.000121 秒 |
| 100 次顺序模拟请求墙钟耗时 | 2.024 秒 | 2.135 秒 |
| 100 次顺序模拟请求 CPU 时间 | 0.954 秒 | 1.000 秒 |

实际服务 RSS 降低约 7.9 MiB / 12%。CPU 的确定性变化是取消无积压时的恢复轮询；实际 TCP 进程还包括 Uvicorn 等后台工作，10 秒窗口内 CPU 为 0.01–0.03 秒，采样粒度为 0.01 秒，不能据此宣称整个服务 CPU 同比例下降。短请求测量也未显示吞吐提升，不将这次优化描述为转发加速。

进程内比较使用同一份 `scripts/measure_runtime.py --idle-seconds 10 --requests 100`，通过 `PYTHONPATH` 分别加载基线源码副本与修改后源码。每次先完成一次预热，再空闲 10 秒并顺序执行 100 次生成，均由内存模拟上游返回；每次总计 101 次调用、1,414 个合成 Token，没有额外调用或重复统计。

实际 TCP 比较通过相同解释器执行 `python -m selark --config-dir <临时目录> serve`，上游为 `verify_stability.Fixture` 的随机本机端口。启动后请求一次 `/health` 和一次模拟生成，关闭测量客户端并预热 1.1 秒，再从 `/proc/<pid>/status` 与 `/proc/<pid>/stat` 记录 10 秒空闲数据；测量后停止该测试进程。该 RSS 仅属于服务进程，不包括父级测量器或模拟上游。每组共三次合成生成。

## 行为回归

- 824 项 Python 回归、23 项前端单元测试、11 项浏览器用例通过；数量保持不变，扩展现有流程断言。
- 恢复流程验证：健康空闲不扫描；落账失败自动唤醒并恢复，清空后继续休眠；恢复不重发生成。保留损坏记录、重启恢复、权限复查、配额和取消测试。
- 普通 API 的多轮与文本分块验证完整消息、Unicode、空白和顺序；同一 `session_id` 的下一次调用只包含本次消息，不补写历史。Anthropic 按原文本转换 system/messages，Responses 只转换调用方输入；Kimi Code 保留调用方思考历史，既有错误与取消测试继续限制生成次数。
- 浏览器验证隐藏标签页两分钟后时间标签不更新，重新可见时读取新快照；时间标签状态已从页面根组件移出。五页、管理表单、移动视口与 401 清空流程仍通过。
- Ruff、差异空白检查、API 契约与前端类型同步检查通过；公开 HTTP 字段未改变。
- 重新打包后，41 项 Dashboard / 前端契约回归通过；wheel 中全部 58 个包文件与源码一致，没有旧哈希资源。真实本机 TCP 的普通/SSE、排队、超时、断开、SIGKILL 重启与退出验收通过，9 次模拟上游调用，无真实模型请求。

这里验证的是 Selark 不注入输入或增加生成次数。模型自身的推理、供应商协议结构与缓存计量不由 Selark 决定，不能将“不增加中转调用”解释成所有模型的 Token 数都必须相同。使用约束见 [资源占用与转发开销](../guides/efficiency.md)。
