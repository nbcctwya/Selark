# Selark 中转站常用场景实测 · 2026-11-01

使用本机已安装的 Selark 0.10.0，对中转站当前启用的 8 个模型标识完成 **80 次真实生成**。
80 次均正常完成转发、响应和用量记账；模型内容仍有分页错误、无效 JSON 和错误的测试预期。
本轮没有发现新的 Selark 网关故障，不能据此把所有模型回答判为正确。

[脱敏逐次统计](relay-common-scenarios-verification-2026-11-01.json) 保留格式、代码执行和人工审阅的不同结果。
原始请求、回复、独立账本及脚本位于 Git 忽略的 `.private/relay-scenarios-20261101/`。
公开报告不含中转地址、密钥、调用方令牌或账户标识。

## 测试方式与范围

所有生成都经过真实的本机 Selark HTTP 服务，再发往现有中转连接；使用已安装构建，
测试前核对安装中的入口、Dashboard、兼容 API 与 ChatGPT 适配器和当前源码一致。
仅发送自造材料，未发送用户文件，也未调用其他来源。

保留日常限额：4 个执行槽、16 个排队槽、排队 10 秒、单次请求总时限 120 秒，供应商超时 60 秒。
44 次普通响应、36 次 SSE；每次最多请求 3,072 个输出 tokens。主矩阵 76 次，另用 4 次
携带真实失败用例的反馈测试检查模型修订能力；无自动重试或跨来源回退。

## 开发任务：运行代码后的结果

主矩阵的 36 份实现有 32 份通过全部边界检查；两份修订实现一份通过、一份仍失败。
合计运行 **9,998 次检查，298 次失败**，分布在 5 个代码版本中。
所有去重版本均通过；失败均来自分页逻辑。

- `opus-5-5` 第二轮在空列表夹取时返回页码 0；第三轮对非空列表启用夹取后，无论请求页码
  是否越界都跳到最后一页。给出真实失败用例后，修订版的 279 项检查全部通过。
- `sonnet-5-5` 第二、三轮，以及反馈后的修订版，仍会返回原始请求页码，未正确反映夹取后的页码。
  例如 `paginate([], 7, 2, clamp=True)` 应返回 `page=1`，实际仍是 7。
  修订版 279 项检查中仍有 72 项失败。
- 以最新一次实现计算，8 个模型的分页任务有 7 个通过；4 个深测模型的最终去重实现全部通过。

代码使用 [独立执行检查器](../../scripts/check_application_code.py)，在离线受限子进程中执行。
先检查 AST 和允许的操作，再限制 CPU、内存和文件写入；仅执行选定函数，不执行答案中附带的示例脚本。
测试覆盖错误类型、布尔值冒充整数、空输入、越界、夹取前后的页码与标志、输出复制和输入不变性。

检查器最初误拦了 6 份使用正常 `str.isspace()` 校验的去重实现。审阅后仅补充此允许方法，
复用原回复重新离线执行，6 份全部通过，没有因此多发付费请求。
新增一项针对该误拦的回归，检查器的 3 项测试全部通过；最初误拦结果另行保留。
本轮没有将模型生成代码写入 Selark 产品逻辑。

## JSON、翻译和长文

42 份要求 JSON 的回复中，24 份可直接解析，18 份不能直接使用：16 份带 Markdown 围栏；
另 2 份是反馈后去掉围栏、但内容仍无效的翻译回复。所有这些格式失败均来自默认 `sonnet-4-6`
和 `sonnet-5-5`，并非网络错误。

4 份初始翻译和 2 份修订翻译都出现未转义的字符串内双引号，形如：

```text
"action": "如果连接失败，请选择"离线工作"并联系 {support_email}。"
```

因此，去掉围栏也不足以修复。追加提示明确指出引号问题并要求使用中文引号，两个模型仍保留
无效双引号。原始答案保持不变，网关没有替模型清洗或补写 JSON。
这轮是通过提示要求 JSON，没有发送 `response_format` 或工具参数约束，不能推广为所有结构化生成模式。

诊断性提取围栏内容后，另外 12 份围栏回复可解析，其中一个设计回复还附带额外说明。
8 份开发记录的字段和值、4 份长文证据、4 份并发标记在这一诊断中均正确；原始格式失败仍保留。
长文请求实际出站正文为 19,034–19,036 字节，未观察到材料中的伪指令覆盖取值任务。
这只验证了这组自造长文和伪指令，不是全面的提示注入防护证明。

冒烟题的统计另外做了公平性修正：提示要求一个标记和算术值，但没有明确规定字面字段名。
3 个模型返回 `{标记: 算术值}`，初版检查器只接受 `{"marker": 标记, "value": 算术值}`。
这 3 份原始 JSON 的计算和标记正确，属于题目歧义，不能算模型错误；另 2 份带围栏的同类答案
仍违反明确的“无 Markdown”要求。原始检查结果和修正依据均保留在 JSON 中。

## 人工审阅发现的额外问题

自动字段检查不足以评估审查与设计建议。4 份代码审查均提到了五类缺陷，行号正确，
但人工检查发现：

- `opus-5-5` 提供了错误的测试预期：`[1,2,3]` 的第 2 页、每页 2 项应是 `[3]`，
  却写成 `[2,3]`；排序后的 `[9,8]` 第 1 页、每页 1 项应为 `[8]`，却写成 `[8,9]`。
- 两个深测 Sonnet 的参数校验建议只补充拒绝 bool，漏掉 0 和负数。
  建议用 `id(items)` 区分缓存，也没有处理同一可变对象内容发生变化后的缓存失效。
- 默认 `sonnet-4-6` 的工具设计建议恢复时先复制覆盖主库、再检查完整性；该流程缺少恢复前
  验证和保留原库的保护。`sonnet-5-5` 的方案没有说明如何生成一致的 SQLite 备份快照。

上述问题都来自本轮生成的示例和设计文本，**不是 Selark 当前代码中的同名缺陷**。
方案中的离线、无遥测、预算未知等约束基本保留，但仍需要工程审阅，不能直接照单实现。

合并独立代码执行，并排除 3 个有歧义的冒烟判定后，57 / 80 次满足本轮的可自动核验要求；
人工发现的问题另列，未伪装成自动检查已覆盖。这个数字不是综合质量分数，也不表示 57 份回答
在全部语义上均正确。

## 网关、用量与收尾

80 次都以 `stop` 结束；80 条独立账本记录、80 次上游尝试，用量逐条匹配，未知用量、
多次尝试、遗留 running 均为 0。四路并发观察到 4 个活动槽，队列峰值为 0；
结束时 active、queued、admitted 和待落账均为 0，存储未降级。

262 次健康检查无失败，P95 为 2.96 ms，最大 24.29 ms。
全部请求端到端耗时中位数 8.22 秒，P95 为 22.15 秒；这是有限场景的短时观测。
本轮没有观察到报告输出量超过请求上限，但未重跑小上限压力用例，
不能据此否定 [此前的输出上限异常](relay-stress-verification.md)。

| 中转上报字段 | 合计 |
| --- | ---: |
| 输入 tokens | 379,741 |
| 输出 tokens | 45,126 |
| 总 tokens | **424,867** |

缓存明细没有重复叠加。默认 `sonnet-4-6` 的 15 次调用上报总量 307,038 tokens；
其中短冒烟请求上报 13,982 个输入 tokens，同组其他标签为 256 或 1,017。
这是上游自报数据的差异，不能仅凭本地请求推断实际上下文组成、计费倍率或真实模型。
Selark 保留了这些上报值，没有将其改写为本地估计。

本地没有中转定价，未查询账单，**实际金额未知**。
主矩阵及反馈测试分别核对日常连接、客户端、资源、服务配置和日常数据库哈希，均未改变。
使用独立临时账本，因此这些调用不会显示在日常 Dashboard 的历史中；测试实例已停止。

本轮代码变更仅为离线检查器增加 `isspace` 支持及对应回归；没有更换默认模型、启用模型或修改运行时。
检查器定向回归、Ruff 检查、格式检查、Git 差异检查和仓库凭据扫描通过。
