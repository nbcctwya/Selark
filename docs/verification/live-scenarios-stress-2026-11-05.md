# MiMo / 中转站真实场景与压力验收 · 2026-11-05

本轮使用已配置的 MiMo `mimo-v2.6-flash` 和中转站 `claude-sonnet-4-6`，覆盖文案、代码、情绪分析、翻译、日常规划、软件设计、长上下文、多轮 Agent、持续并发、突发、慢速接收和取消。输入均为合成资料，调用真实 API；未调用其他供应商，也未修改日常服务配置。

**568 个客户端请求，475 次上游尝试预留，464 条接纳请求记录全部落盘，恢复积压为 0。** 不能把 475 视为成功生成次数：10 次在连接/连接池阶段终止，465 次收到上游 HTTP 200；其中 455 次完成协议交付，450 次有非空回答，另外包含主动取消和流内错误。

测试从北京时间 **15:43:13 至 16:29:20**，含阶段之间的检查约 46 分钟；测试器累计运行约 40 分 55 秒。仓库起点为 `4f7a50e`，运行时代码沿用 `e43a85e`，Python 3.12.2。原始数据与已审阅汇总分别保存；本轮没有修改网关行为。

## 日常任务与回答质量

六类任务各有两个变体，每个变体连续三轮修改要求，两种 API 共 **72 次**。所有 72 次都完成了非空交付。以下是确定性要求检查，不是完整的写作或通用智能排名。

| 场景（每种 API 各 6 次） | MiMo | 中转站 |
| --- | --- | --- |
| 中文介绍与改稿 | 5/6 满足检查；1 次不足指定汉字数 | 1/6 满足检查；其余主要超出指定汉字数 |
| Python 分页、去重与需求变更 | 5/6 通过执行检查；1 份去重实现有边界错误 | 6/6 通过执行检查 |
| 情绪分析 | 69/72 个标签正确；还存在证据引文删空格的问题 | 去掉完整代码块后，5 份可解析回复的 60 个标签均正确；另 1 份仍无法解析 |
| 翻译与字段保留 | 6/6 通过 | 原文均不满足纯 JSON；去掉代码块后 3/6 通过，另 3 份有未转义引号等格式问题 |
| 日常规划与记忆修订 | 6/6 通过 | 去掉代码块后 4/6 通过，另 2 份内容中的 JSON 仍有未转义引号 |
| 软件设计与约束修订 | 3/6 严格通过；去掉代码块后 6/6 通过 | 原文均带代码块；去掉后 6/6 通过 |

MiMo 的代码失败为 `s0005.mimo-default.relay`：需求要求同一组最高版本并列时取最后一次出现，实现却保留了较早记录。465 项边界检查中失败 39 项。它没有传输错误，说明“返回了代码”和“代码正确”必须分开核验。

全部阶段共收集 73 份代码回答：受限离线检查器确认 59 份通过、1 份有功能错误；另外 13 份没有进入功能执行，其中 9 份被检查器的属性白名单限制，4 份未找到恰好一个目标函数实现。未执行样本不能当作代码正确，也不能一概当作模型功能错误。检查器不是任意代码的通用沙箱。

MiMo 对 S08 的三次错误把引述他人的负面评价计入了作者态度；中转站的主要结构化问题是回答中的 JSON 格式。这里说的是 `message.content` 中模型生成的内容，**不是外层 API 响应 JSON 损坏**。直连对照也复现了加代码块的行为。

本轮修正了离线评分器：原先使用单词边界，导致“保留14天”这样的正确中文文本被误判。现在使用数字边界，已检查中文紧邻、空格、英文以及错误数字。原始评分与回复均保留，表中使用修正后的离线评分；没有修改模型回答。

## 长上下文、长文与 Agent

**长上下文：**约 8／32／128／256 KiB 的合成日志，在开头、中间、末尾放入三个检索目标，共 16 次直连/中转测试。全部取得正确值，移除完整 JSON 代码块后 16/16 通过。最大样本分别报告 MiMo 82,145、中转站 67,249 个输入 Token；同一目标的直连和中转计数一致。这是固定检索练习，不代表任意大项目推理能力。

**长文：**8 次中文手册、8 次英文技术设计，单次输出上限 8,192 Token。15/16 完成协议；MiMo 的 `s0119` 在持续生成时达到测试核心 180 秒总时限，返回 `request_deadline_exceeded`，完整用量未知。MiMo 已完成的中文样本耗时约 63–143 秒，流式首段可在约 0.8–1 秒到达。

长文的主题覆盖与长度要求分别检查：8 篇中文手册均未落入要求的 2,500–3,200 汉字范围，实际约 2,150–4,712 汉字。英文设计按含代码的英文词统计，仅中转站 3 份落入 1,800–2,400 词范围；该计数方式只作机械参考。不能将 15 次传输完成解释为 15 次完全符合写作要求。

**24 轮需求记忆：**持续改变平台、保留期、导出格式与备份安排，同时保留离线、无遥测、禁止付费重试、未知预算及最初校验码。MiMo 24/24 同时满足纯 JSON 与状态值；中转站 24/24 状态值正确，但都添加了代码块，严格格式检查为 0/24。

**多步工具 Agent：**调用方维护历史，并执行只允许访问固定合成库存的 `list_items`、`read_item`、`calculate_order`、`save_order`。没有执行模型生成的 shell、文件或网络操作。

| 调用方方式 | MiMo | 中转站 |
| --- | --- | --- |
| 严格解析纯 JSON 动作 | 26 步完成，8 项库存结果全部正确 | 第 1 步加入说明文字，无法解析，停止 |
| 仅允许去掉完整 JSON 代码块 | 无需重复测试 | 第 1 步仍含前置说明，停止 |
| 只提取唯一、符合动作字段的 JSON 对象 | 无需重复测试 | 26 步完成，8 项库存结果全部正确 |

最后一项拒绝多动作歧义，工具参数仍逐项校验；原始回答及后续历史没有改写。三种方式是单独的调用方测试，不是网关自动修复或重试。**Selark 当前仍不支持原生 `tools` / `tool_calls`；两次原生工具请求均在本机返回 400，未调用上游。** 不能将本次文本动作流程写成已兼容任意原生 Agent 客户端。

原三组持续负载中 MiMo 承担文案/情绪分析，中转站承担代码/设计，任务组合不同，不能据其耗时给模型排速度名次。补充组让两种 API 都接受相同的四类任务、两个变体及普通/流式模式；使用全新进程，并降低驱动端整份报告的写盘频率。

补充组观测到 16 个同时活跃请求，端到端时间如下，包含生成、网络和本机处理：

| 目标 | 流式非空首段中位数 / 最慢（各 8 次） | 完整响应中位数 / 最慢 |
| --- | --- | --- |
| MiMo | 1.13 / 5.09 秒 | 19.95 / 59.45 秒（16 次完整） |
| 中转站 | 2.62 / 5.63 秒 | 10.64 / 22.80 秒（15 次完整；另 1 次连接失败） |

这不是相同输出长度的模型速度基准，也不是本机额外延迟。小样本 p95 很容易等于最大值，不提供稳定尾延迟保证。

共观察到 **6 次连接池等待超时、2 次连接超时、2 次连接失败、1 次直连流内错误、1 次 180 秒总时限超时**。连接池超时在混合突发及持续 16 并发中复现；新核心补充组没有复现。新增连接池观测在补充组收尾、进入下一场景前记录到 0 个池内请求与 0 个排队请求，不能据此证明原异常已修复。尚未确定原因是否与连接状态、代理、取消清理或测试观测开销有关。

两次突发后的恢复批次各 8 次均完成协议；默认核心恢复批次有 1 次中转站空回复，不能称为全部有效回答。慢速接收按 SSE 事件延迟 20 ms，并未突破 TCP 缓冲区来证明无限背压能力；取消后没有自动补发，未知用量保持未知。

CPU/RSS 只统计临时核心 PID，驱动端在另一进程。主测试的默认/高并发核心使用 `fork`；高并发核心继承了驱动端累计结果的内存页，冷启动就有 74.40 MiB，负载后达 82.17 MiB，**不能把这个差额归因于 Selark 泄漏或并发本身**。该核心 16 并发阶段 CPU 平均约单核 5.25%。补充组使用 `spawn`，避免继承驱动端结果堆；不同启动方式、负载和观测条件的数值不直接相减。

测试保留鉴权、队列、配额、持久结算和恢复。测试器额外做预算/证据 fsync、请求观测、健康轮询和报告写盘，均带来开销。健康探测全部取得响应，但主突发阶段曾观测到约 2.25 秒的探测耗时；驱动端同步写盘也会推迟它读取响应，不能将该数字直接解释为健康接口服务端耗时。

真实上游使用现有代理环境，本机客户端忽略系统代理。直连 HTTP 超时为 180 秒、外层 200 秒；网关测试设置连接超时 10 秒、连接池等待 5 秒、上游读取 150 秒、总时限 180 秒。队列等待为默认组 10 秒、高并发组 60 秒。它们是本次隔离测试参数，没有改写日常配置。

本轮不是长时间内存泄漏验收，也不认证本机 p95 额外延迟已低于 10 ms；正式性能预算继续使用[同环境模拟对照](latency-verification-2026-11-05.md)。

## 用量异常与后续重点

中转站的 5 次空回复全部是正常结束的流式响应，均报告 0 输出 Token。相同完整请求的输入计数仍有变化，例如 209→257、558→597；这些变化有时伴随空回复。`s0424.relay-personal.relay` 有 2,569 字符的回复，却报告 0 输入、1,545 输出 Token；同一请求其他样本报告 558 输入。原值保留并入账，不把它修成猜测值，也不推断实际账单或第三方内部原因。

优先调查连接池等待超时，并使用低观测开销的独立复现区分核心、代理与驱动端影响。长任务需要明确总时限与流式活跃期间的超时策略；不能自动重试已可能收费的生成。结构化输出与文本动作的兼容应由调用方显式处理，保持 Selark 原样转发；原生工具协议支持应作为单独能力实现和验收。
