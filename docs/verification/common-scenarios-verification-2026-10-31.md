# Selark 常见场景模拟与 MiMo 实测 · 2026-10-31

本轮测试：203 次真实 MiMo 生成、203 次协议正常结束、158 次满足全部自动内容检查；另有 8 应用、1,376 次请求的模拟故障/并发验收，52 项检查全部通过。

真实请求使用已安装的修复构建，经过 Selark 本机 HTTP 文本网关，只发送自造材料。三个模型均来自现有启用清单。临时实例容量设为 8 执行 + 8 排队，请求总时限 330 秒；日常实例配置未改，原值为 4 执行 + 16 排队、排队 10 秒、请求总时限 120 秒。多轮请求携带真实的前轮回复，普通与 SSE 交替；未要求额外思考参数。正常协议结束包含明确的 length 结束；触达输出上限的回复单独记为内容未通过。

## 日常任务与多轮修订

每个模型运行 6 类任务、每类 2 套材料、每套 3 轮，共 36 次：语气分类及逐字证据、中英双向翻译、分页/去重代码、依据事实档案写作、个人计划及记忆修订、离线软件方案设计。第二/三轮会修改时间、人数、留存期限或代码规则，要求沿用正确历史并覆盖旧事实。

| 模型 | 多轮请求 | 协议正常结束 | 全部自动内容检查通过 |
| --- | ---: | ---: | ---: |
| Flash | 36 | 36 | 25 |
| Pro | 36 | 36 | 28 |
| Pro UltraSpeed | 36 | 36 | 26 |

代码项目以独立执行结果为准，格式通过但执行失败记为未通过。“自动内容检查通过”只说明可程序化核对的要求通过，不能保证整篇回答事实正确。写作/方案类尤其需要人工审阅；本轮抽查发现自动数字与字段检查未覆盖的无来源细节。

## 长文、缓存和并发

长文材料在不同位置埋入自造证据，检查 JSON 原样提取；重复前缀请求检查缓存用量是否由上游报告。并发分别使用 1、4、8 个同时请求，混合普通和 SSE。长输出覆盖离线知识库设计、网关故障手册、文档助手验收方案，并加入低内存、离线、共享电脑、大数据量、磁盘满、慢网络、新用户、升级回滚等约束。

| 场景 | 请求 | 协议正常结束 | 自动检查通过 |
| --- | ---: | ---: | ---: |
| 长文证据提取 | 9 | 9 | 1 |
| 重复前缀缓存 | 3 | 3 | 1 |
| 并发 1/4/8 | 26 | 26 | 26 |
| 长篇实用方案 | 55 | 55 | 49 |
| 追加长文提取 | 2 | 2 | 2 |

长篇方案自动验收只覆盖最小长度和关键主题，不代表其中所有设计建议均已实现或验证。首批低内存场景目标 6000 汉字、上限 12288 tokens；其中 Flash 验收方案用满上限，以 length 结束，记为内容未通过。后续目标 3500 汉字、上限 8192 tokens，并发从 3 提高到 8；后续仍有 1 条 Flash 回复用满 8192 上限，本轮共 2 条内容截断。切换前等待在途请求结束；3 条本地控制暂停请求均为 0 上游尝试，不计入真实生成。缓存缺失不补零，不把重复输入等同于缓存命中。

格式诊断：28 次失败回复仅包裹一层 JSON 围栏；诊断性移除围栏后，21 次满足其余自动要求，另 7 次仍有字段/内容错误。原始结果仍全部记为未通过，网关和原始回复没有被清洗。

初始 9 次长文提取的值均与预期一致，其中 8 次违反纯 JSON 格式。3 次前缀缓存请求均上报 43,136 缓存 tokens / 43,177 输入 tokens。

## 生成代码的独立执行验证

共 18 个代码版本，17 个通过全部边界测试；累计执行 4,944 次断言，50 次失败。测试覆盖空/越界分页、参数类型与布尔值、夹取最后一页、状态字段、去重顺序、调用方隔离和 revision 规则。

执行在受限环境中使用现有 `check_application_code.py`，先做 AST 允许列表校验，再限制 CPU、内存和文件写入。只执行选定函数定义，不执行模型给出的示例脚本，也不联网。

## 实际发现

日常配置的单次总时限是 120 秒，而部分长文实测耗时超过 120 秒。因此 330 秒测试实例中的成功不保证原配置下也能完成；同样速度的长生成在日常实例中会先触及总时限。需要完整长文时，可缩短生成目标或按需要调整时限；本轮没有修改日常限额。

- `sentiment-a-mimo-v2.6-flash-1`：逐字引文被改写或拼接。S01 删除中间内容后拼接两段原文；S04 删除版本号前空格；S11/S12 改写原句。自动逐字检查失败属实。
- `chat-a-mimo-v2.6-flash-1`：要求纯 JSON，但输出包裹 Markdown 代码围栏；严格 JSON 解析失败属实。
- `article-b-mimo-v2.6-flash-3`：事实档案未提供菜单位置，回答却写出“帮助—关于—日志”的具体路径，属于无来源补充；自动事实数字检查不足以发现这种问题。
- `chat-b-mimo-v2.6-flash-3`：抽查最终 profile 保留小岚、周三 25 分钟/周四 15 分钟，城市及预算仍为 null，question 为 null，符合本轮自动检查项。此检查不代表整个学习建议经过全面认证。
- `article-a-mimo-v2.6-pro-1`：要求 500—700 汉字介绍，实际仅复述档案开头一句，22 个输出 tokens 即正常 stop；明确属于任务未完成，不是网络截断或输出上限。
- `coding-b-mimo-v2.6-pro-ultraspeed-3`：代码格式检查通过，但独立执行 465 项边界中失败 50 项：每次遇到新 ID 都执行 selected_revision = {key: revision}，清空先前 ID 的版本号，后续旧 ID 引发 KeyError。最小序列为 a(rev=3)、b(rev=1)、a(rev=2)，prefer=highest_revision。此为生成代码错误，不是 Selark 网关错误。
- `practical-longform-0-longform-evaluation-design-mimo-v2.6-flash-mimo-v2.6-flash`：运行约 321.64 秒，用满 12288 输出 tokens，finish_reason=length。用量完整，输出上限生效；即使长度/关键词检查通过，也不能把截断回复当作完整内容通过。
- `diagnostic-manual-code-fix`：对失败去重函数做独立定位：将版本号字典初始化移到循环外，每个新 ID 仅写入对应键。相同 465 项执行测试全部通过，确认失败来自该状态覆盖。原模型答案和 50 项失败结果保留，补丁没有写入 Selark 产品代码。
- `practical-longform-6-longform-offline-design-mimo-v2.6-flash-mimo-v2.6-flash`：首次使用新用户条件下的知识库方案运行约 191.81 秒，用满 8192 输出 tokens，以 length 结束；与首批 12288 上限样本一起，共 2 条回复标为内容截断。

全部自动检查失败明细见 JSON；没有清洗围栏、改写模型答案或重试生成来掩盖失败。

## 多应用与故障模拟

`verify_multi_app.py --requests-per-app 100 --four-api --burst-clients 64 --burst-cycles 3` 使用模拟上游，真实供应商调用数为 0。8 个应用用独立令牌和 HTTP 连接池，先完成 800 次稳定调用，再注入突发并发、错误和权限边界。

52 项检查覆盖：相同 session ID 的应用隔离、四来源共享队列、64 请求突发的容量拒绝、排队取消/超时不发上游、单来源限流/鉴权/服务错误/断流隔离、令牌与金额配额并发预留、未知用量保留、撤销权限、重启后账本及预留保留。容量上限为 4 执行 + 8 排队，过载时预期拒绝；这些预期错误不算模型故障。

共 1,376 次客户端请求、983 次模拟上游请求。最后活动/排队/待落账均为 0，临时服务停止，模拟客户端文件清理完成。

## MiMo 用量与费用估算

本轮上游报告 1,558,902 输入 tokens、276,351 输出 tokens，共 1,835,253 tokens。依据报告用量及官方单价，估算金额或保守上界为 **¥5.644866**；另保留未知用量预留 ¥0。

使用单次发送前费用预留，只有账本确认最终 token 用量后才结算；若缺少缓存命中细分，按未打折输入价计算保守上界。测试脚本曾因缓存细分缺失、UltraSpeed 附带性能统计而暂停核对；核实最终计费字段与台账一致后沿用原报告和费用继续，未重复发送。追加测试累计限额 ¥5.75，余量留给此前短请求和计价误差；未查看官方实际余额，也未自动充值或更换付费来源。

采用的 CNY/百万 tokens 单价如下，来自 [MiMo 按量付费说明](https://mimo.mi.com/docs/zh-CN/price/pay-as-you-go)：

| --- | ---: | ---: | ---: |
| Flash | 1 | 0.02 | 2 |
| Pro | 3 | 0.025 | 6 |

估算不等于账单扣款或真实剩余额度。此前六来源复测中 MiMo 的 13 次请求，按相同官方单价全价估算约 ¥0.00323，单独留有余量。

本轮停止原因：`finite_suite_completed`；因单次预留超过剩余预算而未发送的候选用例 46 个（共 47 次预留检查）。没有为了用完尾款重发已经完成的任务。

原连接配置、启用清单、默认模型和客户端配置哈希未变。使用独立测试账本，日常 Dashboard 记录不包含这批测试。测试结束后临时监听停止。
