## 复现与修复

修复前新增的首批 14 个回归全部失败，分别复现以下三类问题；修复后这些回归全部通过。

1. **取消时留下不应存在的配额占用。** 数据库线程已经提交预留，而等待它的异步请求
   恰好被取消，服务尚未发出上游 HTTP 请求。原逻辑仍将预留变成 `unknown_hold`，可能
   阻止该调用方当天继续调用。现在只有最终收据明确记录 `0 / not_started` 时释放预留；
   请求记录及其取消/超时/关闭状态仍保留，不编造用量。没有收据的异常退出仍保留未知占用。
2. **动态别名的用途标签过期。** 排队期间管理员将别名从套餐改到普通 API，最终连接归属
   正确，但用途仍标为 `interactive_coding` 或 `interactive_task`。现在按最终 API 目标
   还原为 `chat`，合法的 `connection_probe` 保持不变；套餐名额仍释放并重新检查。
3. **异常上游数据被误认为成功。** 普通响应原本不验证结束原因、choice 序号及 assistant
   角色；SSE 可能接受多条 choice、非字符串结束原因或结束后的新增文本。现在校验文本
   子集，普通异常返回 502，流中异常发 `event: error`，不附成功 `[DONE]`。
   异常之前有效帧中的部分用量保留，但不伪装成最终用量；名额与响应对象均释放。

校验参照 [DeepSeek 官方 Chat Completions 响应定义](https://api-docs.deepseek.com/api/create-chat-completion/)
中 choice 索引、assistant 角色和结束原因的类型。没有把厂商结束原因限定成固定枚举，
`stop`、`length`、`content_filter`、`aborted` 等字符串继续透传。
支持合法的空 choices 用量帧和重复累计快照，不将重复上报计为多次消耗。
传输完成和内容任务成功仍是不同概念：如 `length` 仅表示达到上限，不能视为回答完整。

全部使用临时配置、临时 SQLite/pending、虚构 Key 和 HTTPX MockTransport；没有生产
模拟开关，也没有真实供应商网络回退。[回归代码](../tests/test_coverage_edges.py) 共 40 项：

| 领域 | 案例数 | 检查内容 |

| 取消与预留 | 3 | 提交后、发送前的总超时、任务取消、服务关闭；重启后仍可正常调用 |
| 收据恢复 | 1 | 确定未发送的取消释放预留；无最终证据的异常退出仍未知；重复重放不重复统计 |

| 异常 SSE | 8 | 多 choice、错误序号/类型、空结束原因、结束后继续文本/更改原因；保留此前部分用量 |
| 合法终止兼容 | 8 | 四种结束原因 × 普通/流式；无文本的重复结束和重复用量不重复计费 |

| 只有思考且截断 | 2 | 普通/流式均保留实际报告用量，CLI 提示输出上限，不展示思考或自动重试 |
| 多轮会话并发 | 1 | 四类连接、四调用方、七会话、各四轮，共 28 次模拟生成；逐轮带回上次回答 |
| 排队时撤销 | 1 | 已通过鉴权的排队请求可结束；新请求拒绝；重启后撤销保持 |
| 排队路由/用途变化 | 3 | API→套餐成功、缺少用途被拒绝、排队时收窄套餐用途被拒绝 |

多轮测试同时使用同一调用方的不同会话、不同调用方的同名会话；普通/流式交替，Kimi

撤销语义沿用原有约定：已经通过鉴权的执行中或排队请求不被追溯取消，新鉴权拒绝。
权限、模型、套餐用途、输出和日额度在分发前再次检查。连接别名只因管理员显式修改而
改变目标，没有自动重试或付费回退。

## 覆盖边界

- 此次检查未新增真实模型调用；之前中转站反复 400、协议错误和超时的情况仍未证实恢复。
  中转站六类任务仍没有完成全部三轮真实对话，不能用本轮模拟补记成功。
- 此前真实长文本最大单次输入 89,171 字符；没有对每个模型压到完整上下文上限，也没有
  数小时/数天的持续压力、厂商全部限流阈值或全部返回错误的真实测试。
- 仍只支持已声明的文本子集，不新增工具执行、多模态、结构化输出保证或自动上下文管理。
  模型的事实准确性、翻译质量、文章字数等需要内容验收；HTTP 200 与结束标记不等于任务正确。
- 实际断电、磁盘硬件损坏、真实厂商对取消的计费时点没有实测；模拟进程退出、锁竞争、
  写入失败和重启恢复不能证明这些外部行为。未知消耗继续保持未知。
- 更严格的回复校验会拒绝缺失必要字段或多 choice 的不规范中转响应；不会猜测、拼接
  不同回答或为绕过协议问题自动换来源。
- Python 3.11/3.13 的远程 CI 留待后续推送执行；本机本次使用 Python 3.12.2。
