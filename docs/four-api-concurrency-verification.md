# 四 API 并发与极端场景验收

2026-10-30，Selark 0.7.2 工作区。OpenAI、DeepSeek、MiMo 与中转站共同参与测试。
**模拟压力验收通过；真实验收发现中转站内容偏差与输出上限异常，不能视为全部通过。**

本轮新增验收脚本、模拟回归与 CI 步骤，没有修改网关运行时代码。真实调用使用既有的
三个 API 连接和用户提供的 OpenAI Key；测试只在临时配置、临时调用方和临时账本中运行。

## 模拟压力结果

[verify_multi_app.py](../scripts/verify_multi_app.py) 使用真实本机 HTTP、独立客户端连接池
与调用方令牌；供应商全部由 `httpx.MockTransport` 模拟，不连接真实供应商。

| 项目 | 实测结果 |
| --- | --- |
| API / 独立应用 | 4 / 8，每个 API 两个应用 |
| 客户端请求 | 1,824，包含 1 次排队期间客户端主动取消 |
| 模拟上游请求 | 984，无自动重试 |
| 检查 | 52 / 52 通过 |
| 稳态普通与流式调用 | 800 次，内容与调用方归属全部正确 |
| 同时执行 / 排队上限 | 4 / 8 |
| 同时在途的不同 API | 4 |
| 各 API 独立压力峰值 | 每个均达到 4 个同时执行请求 |
| 真实生成 / 供应商元数据 / OAuth 操作 | 0 / 0 / 0 |

执行了三轮混合突发及四轮单 API 突发，每轮 128 个客户端请求。每轮均有 12 个请求进入
上游，116 个返回 `server_overloaded`；没有突破 4 个执行槽和 8 个排队槽。

覆盖的边界如下：

- 四个 API 分别注入 429、401、503、读取超时、无效 JSON、截断 SSE、客户端断连和
  缺少用量，共 32 组故障；每组同时调用另一正常 API，确认正常请求完成且无重复尝试。
- 排队取消与排队超时均未发送上游请求，执行槽和队列随后恢复为空。
- 同名会话按调用方隔离；客户端伪造身份、越权连接与模型访问被拒绝。
- 应用并发、Token 配额和预算的并发预留，未知用量保留，单应用令牌撤销与其他应用恢复。
- 每次响应只归属一个调用方，用量不重复计算；重新打开账本后统计与未知预留保持一致。

共享入口仍有现有边界：高流量应用被拒绝和记录落账期间，邻近请求可能短暂收到过载；
本轮有 4 个邻近请求遇到该情况，清理后其余 7 个应用均成功调用。共享队列不保证每个
应用独享执行槽。并发上限为 1 时，响应已交付而账本尚在落盘的短窗口也可能拒绝下一请求。

模拟成功请求延迟 P50 为 150.05 ms、P95 为 575.12 ms，最大 984.18 ms；这些数值包含
人工延迟和本机处理，不能当作真实模型速度。最终 active、queued、admitted、pending
均为 0，恢复检查全部为 0，临时服务与配置已清理。

旧六应用模式另做兼容性复测：126 次客户端请求、65 次模拟上游请求，12 项检查全部通过。

## 28 次真实 API 调用

[verify_four_api_live.py](../scripts/verify_four_api_live.py) 为每个 API 分配两个临时调用方。
每个 API 最多 7 次尝试、总计最多 28 次，没有重试或来源切换。普通请求的输出上限为
OpenAI 256 tokens、其他 API 64 tokens，截断测试均为 8 tokens；每个出站请求体最多
1,200 字节。它们是请求约束，不能保证上游实际计费必然遵守。

阶段为：每个 API 一次普通和一次流式调用（8 次）、四 API 的八客户端混合调用（8 次）、
四路输出截断（4 次）、四路流式首段后主动取消（4 次）、取消后再次调用（4 次）。

28 次请求均返回 HTTP 200；其中 24 次正常结束，4 次按测试要求取消。混合阶段观察到
4 个执行、4 个排队；根据出站发送至收到响应头的重叠区间，确认 **4 个不同 API 同时在途**。

| API | 请求模型 | 普通 / 流式 / 恢复内容检查 | 8-token 截断 | 主动取消 | 已知 tokens |
| --- | --- | --- | --- | --- | ---: |
| OpenAI | `gpt-6-luna` | 5 / 5 正确 | 8，`length` | 已取消，用量未知 | 210 |
| DeepSeek | `deepseek-flash` | 5 / 5 正确 | 8，`length` | 已取消，用量未知 | 176 |
| MiMo | `mimo-v2.6-flash` | 5 / 5 正确 | 8，`length` | 已取消，用量未知 | 177 |
| 中转站 | `claude-sonnet-4-6` | **3 / 5 正确** | **974，`stop`，超出请求上限** | 已取消，用量未知 | 30,658 |

内容检查要求精确返回一个带调用方与阶段标记的短字符串。中转站在混合流式及取消后的
恢复请求中没有返回指定字符串。恢复请求的 HTTP 200 证明能够再次调用，并不代表答案正确。

OpenAI 的 8-token 截断全部用于推理，未产生可见文本，但返回 `length` 和 8 个输出
tokens，符合这项截断测试的预期，不能归类为普通答案检查失败。

### 中转站异常

截断请求携带 `max_tokens=8`，中转站最终报告输入 11,848、输出 974、合计 12,822 tokens，
结束原因为 `stop`，返回 3,892 个可见字符。之前两个短字符串请求也分别报告 9,320 和
8,249 个输入 tokens。已知用量按上游原始报告保留，不把异常数字替换成请求上限。

本轮未查询中转站账单或内部路由，无法确定输入计数偏大的原因、实际模型身份或最终扣费。
这条连接尚未通过输出上限和稳定内容返回的验收。

原始实测脚本当时尚未对“已返回的用量超过输出上限”自动停止；人工停止标记写入前，
28 次已全部执行结束，没有追加真实请求。事后已补充以下保护，仅用模拟响应验证：

- 一旦报告的输出用量超过请求上限，写入停止标记，阻止尚未发送的请求与后续阶段。
  已发送请求的消耗不能由该保护撤销。
- 明确区分传输完成、内容正确、输出上限及预期取消；验收未通过时脚本返回非零退出码。
- 出站前持久记录尝试次数，失败不退还次数；已有预算目录不能被重复使用以重置计数。
- 记录实际输出参数名与请求体 SHA-256，后续排查无需保存密钥或请求正文。

不能将本次真实结果描述为已经验证了新增的自动停止保护。

### 用量、费用与清理

24 次完整请求的已知用量合计 **31,221 tokens**：

| API | 输入 | 输出 | 合计 |
| --- | ---: | ---: | ---: |
| OpenAI | 108 | 102 | 210 |
| DeepSeek | 113 | 63 | 176 |
| MiMo | 127 | 50 | 177 |
| 中转站 | 29,605 | 1,053 | 30,658 |

4 次取消请求均记录为 `cancelled`、交付断连、最终用量未知，各只有一次上游尝试。
未知不等于 0，也不能将上表当作全部扣费用量。OpenAI 文档同样说明，流式连接中断时
可能收不到最终用量块。见 [Chat Completions 流式响应](https://developers.openai.com/api/reference/resources/chat/subresources/completions/streaming-events)。

OpenAI 这轮已知部分按测试日 Luna Standard 输入 $0.10 / 百万、输出 $0.50 / 百万
估算为 **$0.0000618**，不含一次取消后的未知消耗；其余连接及中转站不据此推算账单，
也未查询账户余额。价格见 [GPT-6 Luna](https://developers.openai.com/api/docs/models/gpt-6-luna)。

全部调用的账本归属与已报告用量核对通过。最后没有在途、排队或待落账记录，重新打开
账本的恢复计数全部为 0。原有配置的内容哈希保持一致；测试目录未写入供应商 Key，
临时调用方、服务及数据库已清理。

原始报告和停止标记仅保留在被 Git 忽略的 `.private/` 内。此公开摘要不包含密钥、
授权头、中转站地址、账户标识、请求 ID 或本机绝对路径。

## 复现与自动化

无需密钥、不会消耗 API 额度的相同压力规模：

```bash
PYTHONPATH=src .venv/bin/python scripts/verify_multi_app.py \
  --four-api --requests-per-app 100 --burst-clients 128 --burst-cycles 3 \
  --output /tmp/selark-four-api-simulation.json
```

CI 在 Python 3.12 加入相同的四 API 模拟步骤，原六应用步骤继续保留。真实脚本没有加入 CI。

真实脚本需要显式 `--execute` 与一个全新的工作目录；OpenAI Key 从隐藏输入或
`OPENAI_API_KEY` 读取。其他连接从用户配置读取，默认选取 `deepseek-personal`、
`relay-personal` 和旧 MiMo 默认连接。再次执行会产生新的付费请求；本轮没有重跑。

[付费验收保护测试](../tests/test_four_api_live_harness.py) 的 9 项模拟回归覆盖并发尝试
预留、失败不退款、目录不可重置、目的地 / 模型 / 输出 / 输入 / 凭据约束、停止标记、
上游忽略输出上限，以及截断、取消和错误答案的分类。

最终本机 Python 3.12 完整回归 **559 项通过**（64.82 秒），Ruff 检查与格式检查通过。
新增 CI 步骤尚未在远端运行。发布候选文件的既有密钥精确匹配与常见凭据格式扫描未发现
匹配；原始真实报告、预算文件与模拟明细均确认被 `.gitignore` 排除。
