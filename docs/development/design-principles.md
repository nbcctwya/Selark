# 硬性设计原则与性能预算

Selark 是本机模型转发和资源管理核心。**运行时零额外模型调用、零自动提示文本、低常驻开销**是后续功能、重构和平台移植必须遵守的设计原则。

## 不可破坏的运行时约束

| 项目 | 要求 | 验收方式 |
| --- | --- | --- |
| 额外模型调用 | 0 次；接纳的生成请求至多派发一次 | 捕获上游请求；检查正常、失败、取消与恢复的调用次数 |
| 自动添加提示 | 0 Token；不追加任何提示文本，包括 system/developer 消息 | 比较完整上游消息、文本分块、空白与顺序 |
| 回复二次加工 | 不调用 LLM 做摘要、翻译、润色、审查或修复 | 上游调用次数与回复协议测试 |
| 会话历史 | 不因 session_id 自动存储或补写上下文 | 同一会话第二次请求只包含调用方此次提交的消息 |
| 管理与后台任务 | 不生成文本，不做模型心跳或自动连通性生成测试 | 启动、空闲、健康/状态查询、Dashboard 刷新均无模型生成 |
| 服务进程 | 单个常驻核心进程；Dashboard 按需启动 | 核心启动不拉起 Dashboard、Node/Vite 或额外工作进程 |

鉴权、请求解析、必要的字段映射、流解析、用量记录和恢复是本地确定性处理，不能借助 LLM 完成。协议适配不得制造提示内容；不支持的请求明确拒绝。保持既有契约要求的字段映射与受限文本规范，不擅自删减用户指令来追求数字上的低 Token。

显式执行 `model verify` / `connection probe` 属于用户主动发起的生成任务，须清楚标明会产生供应商用量；不能借此给启动、刷新或转发暗中增加探测。HTTP/OAuth/目录/套餐配额查询不是模型生成，但仍须按需且有界。

“零额外 Token”定义为 **Selark 增加的提示文本为零，Selark 自动增加的模型生成次数为零**。供应商对消息角色、协议结构、缓存与模型推理的计量可能不同；不能保证所有协议的账单数字一致，也不能把未知用量标成零。

## 性能目标与预算

性能必须实测，随机器、解释器和场景注明范围。初始参考场景为 Linux / WSL、Python 3.12、单个普通 API 连接、Dashboard 关闭、默认限流、保留鉴权/配额/日志/落账。

| 指标 | 初始目标 | 判定口径 |
| --- | ---: | --- |
| 核心空闲 CPU | ≤ 0.5% 单个逻辑核，继续接近 0% | 预热后连续 30 秒进程 CPU 时间 / 墙钟时间 × 100 |
| 核心空闲 RSS | ≤ 72 MiB | 参考批次结束后实测约 66 MiB，留约 9% 余量；仅核心 PID，不含测量器、模拟上游或浏览器 |
| 本机 p95 额外延迟 | ≤ 10 ms | 相同模拟上游的逐对“经 Selark − 直连”差值；普通完整响应与 SSE 首段文本分别统计 |
| 健康空闲恢复扫描 | 0 次 | 无积压、无故障时不扫描恢复目录；出现故障须能自动恢复 |

以上 CPU/RSS 数字是初始参考预算，不是任意机器、模型或长上下文的内存承诺。内存采用完成 610 次中转（含预热）、保留真实落账后的空闲场景；此前约 58 MiB 是单次预热样本，不能直接作为持续运行后的基线。ChatGPT 授权、Responses 文本校验、大上下文、并发与大账本需另列场景，不能混进基线或以此悄悄放宽预算。桌面窗口/浏览器单独测量，关闭窗口后不能保留无用轮询。

**10 ms 是优化目标，未达标必须明确记录。** 不能关闭持久落账、提前放行权限或丢弃真实用量来达标。后续修改应说明是否引入常驻对象、定时器、子进程、重复序列化或额外文件 I/O；预算变更须附新旧测量及理由，不能仅为使检查变绿而调高阈值。

## 开发与发布约束

确定性的零额外生成、消息保真与空闲不扫描由常规 CI 检验。性能报告在固定参考环境验收；共享 CI 同时保留测量结果，但不把受调度影响的延迟当作稳定的机器基准。参考环境可启用严格预算检查，未达标返回非零退出码，报告仍须保存。

共享 CI 的性能采样是独立的非阻断步骤；采样失败必须记录 `failed`、错误类型、已完成样本和可用诊断，不能沿用旧成功报告。确定性约束与功能回归仍阻断 CI。CI 为绿不代表性能预算达标，评审须查看性能报告。

延迟测量必须预热直连与中转路径，保持相同输入、响应、连接方式和单请求并发，交替发送次序。以每一对样本差值计算 p50/p95/p99，使用 nearest-rank 百分位；不能用两个独立 p95 相减，也不能把负差值截断后冒充原始分布。默认至少 300 对/模式，保留所有样本。普通响应测到完整响应接收，SSE 测到第一段真实文本；流完成耗时另报。连接建立、排队、长文和并发另测，不混成一个数字。

测量方法、边界及已有结果见 [资源占用与转发开销](../guides/efficiency.md)。新功能的代码评审与 Claude 前端交接都必须引用本原则。
