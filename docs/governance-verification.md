## 实现与本地验证

- Anthropic 默认 API 版本仍为当前官方 `2026-10-21`，修复已经移除的采样参数转发问题，在产生上游尝试前明确返回 400；可按连接显式选择 `2023-06-01`。版本切换使旧验证结果过期。原生普通/流式用量、缓存组件继续保留。OpenAI 拒绝响应的 null 文本与缓存写入统计得到兼容处理。官方来源及支持范围见 [资源管理说明](governance.md#厂商兼容与工程检查)。原生 Anthropic/OpenAI/Kimi/智谱仅模拟验证。
- 每个调用方可配置连接/模型允许列表、滚动 60 秒请求频率、包含排队的并发数、单次输入估算/输出上限、UTC 日 Token 与估算预算。模型列表按权限过滤，别名解析后检查实际目标，排队后和预留事务中再次检查。旧令牌默认不新增应用限制。

- `tokens create --policy`、`tokens policy/quota`、`aliases`、`prices`、`costs`、`ask --alias` 及 JSON 输出完成。`doctor` 增加资源文件/schema 检查，默认不生成。

## 安装后的本地 TCP 与进程验收

以下使用真正的本机 socket 和新 pipx 服务进程，但上游仍是临时模拟 HTTP 服务，真实供应商请求为 **0**：

```bash
python scripts/verify_stability.py --selark "$HOME/.local/bin/selark" --output /tmp/selark-050-installed-stability.json
python scripts/verify_api_stress.py --selark "$HOME/.local/bin/selark" --output /tmp/selark-050-api-stress.json
```

稳定性脚本通过 9 组检查，共 9 次模拟上游：普通/SSE、排队和过载、读取空闲超时、持续小片段触发总时限、真实 socket 断开、SIGKILL 重启未知用量、SIGTERM 有界退出、恢复后可调用。空闲超时约 1,024 ms，总时限约 1,507 ms，SIGTERM 约 424 ms。

压力脚本通过：**275 次客户端 HTTP 请求、50 次模拟上游尝试**，峰值上游并发 **4**。三轮各 80 个同时请求，每轮 12 个成功、68 个过载拒绝；12 个同时断连释放执行/排队名额；撤销和停用符合既定语义；10 个非法或慢请求未生成；SQLite 写锁与一致备份期间 4 条 SSE 均输出 42 个数据事件、恢复 56 tokens。健康检查约 1.97–2.14 ms，结束时执行/排队/待恢复均为 0，存储未降级。

模拟记录已知用量合计 644 tokens，未知用量保留与已知数分别统计；这些均不进入真实用户数据库。

## 三次真实上游尝试

各请求输出上限 16，短输入；没有自动重试、自动换模型或模型发现生成。发送尝试数由真实账本核对 **20 → 23**。

| 连接 / 请求模型 | 方式与调用方 | 结果 | 输入 | 输出 | 总 Token | 耗时 |
| --- | --- | --- | ---: | ---: | ---: | ---: |
| MiMo / mimo-v2.6-flash | 旧 legacy 令牌，经 `@fast` 普通调用 | 成功、已交付 | 13 | 2 | 15 | 2,399 ms |
| DeepSeek / deepseek-flash | 受限令牌，经 `@coding` 流式调用 | 成功、已交付 | 8 | 1 | 9 | 915 ms |
| 中转 / claude-sonnet-4-6 | 受限令牌，显式连接+模型，多轮输入 | **504 upstream_timeout** | 未知 | 未知 | 未知 | 61,685 ms |

已取得用量：**输入 21、输出 3、合计 24 tokens**，另外 **1 次未知用量**。不能据此认定总消耗仅 24，也不能认定中转站没有产生费用。

中转未返回响应或用量，Selark 关闭连接并记录失败，没有再次请求。额度账本保留该请求的 **535 tokens 输入/输出合计估算预留**，明确标为 `unknown_hold`；受限调用方合计为 DeepSeek 已报告 9 + 未知预留 535 = **544**，不是 544 个实际消耗 tokens。其 2 次调用均未配价格，费用未知。两次成功调用的普通响应/流式最终用量与落账一致。

本轮中转站**未取得成功真实结果**，没有用模拟成功替代。停止新增生成并保留失败状态；中转上游是否生成、计费及慢响应原因无法由当前返回数据确认。原生 Anthropic 的版本修复只做模拟，本轮 relay 仍走 OpenAI 兼容协议，不能算原生 Anthropic 实测。
