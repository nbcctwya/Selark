# ChatGPT 订阅验收 · Selark 0.7.0

日期：2026-10-29。环境：WSL/Linux、Python 3.12.2、当前用户 pipx。
机器可读结果：[chatgpt-verification.json](chatgpt-verification.json)。
使用方式与官方依据：[ChatGPT 接入说明](chatgpt.md)。本报告不包含账号邮箱、注册 ID 或任何凭据。

## 实现结果

- `selark chatgpt login/list/status/refresh/logout/usage`；自己的公开客户端动态注册、
  PKCE S256、state/nonce、官方 JWKS 签名及账户绑定验证、跨进程串行刷新。
- 独立 `chatgpt_subscription` 资源，固定官方 OAuth、模型列表和 Responses 地址；
  没有读取其他客户端凭据、使用网页 backend-api、自动生成重试或收费 API 回退。
- 统一 Chat Completions 文本接口支持普通、流式及显式完整多轮输入。
  原有连接、应用权限、并发/队列、超时、会话、落账和恢复路径继续使用。
- 旧调用方默认无订阅权限；须显式授权连接并配置本地输出预留。
  不伪装支持上游硬输出上限，不把预留、未知用量或订阅消耗写成真实账单。
- 已知的失败终态用量和交付失败后的用量保留；未取得最终用量保持未知。
- OAuth 凭据原子私有存储；备份仅保留注册绑定，恢复后重新授权，避免重放轮换过的刷新令牌。

### 真实链路发现并修复的兼容差异

1. 当前链路的有效 SSE 响应缺少 Content-Type。缺失头部时改由有界 Responses 解析器验证；
   明确错误的内容类型仍报错。没有证据断言是 OpenAI 源站还是链路中的其他组件遗漏该头部。
2. 官方推理地址返回 `response.metadata`，当前公开事件清单未列出。将其视为无决策作用的
   元数据；不据此认定身份、成功、用量或序号。必须取得有效 `response.completed` 才成功。
3. 对照最新官方清单补齐 `response.queued`，但没有声称前三次错误就是由 queued 引起。

## 明确未验证及限制

- 没有真实高并发、长文本、所有发现模型、跨账户或额度耗尽测试；真实成功样本只包含一个模型的两条短请求。
- 真实 `chatgpt refresh` 已验证：首次未到刷新时机时返回 `refresh_performed:false`；
  后续重启验收恰逢允许刷新时机，官方刷新成功，返回 `refresh_performed:true`，新凭据私有保存，
  生成次数仍为 6。没有人为修改过期时间。并发／中断刷新恢复及退出仅模拟验证，真实授权继续保留。
- 套餐剩余额度、重置窗口及金额没有可靠查询接口，均不推算；本地 Token 预留不是上游硬上限。
- 限文本子集；不支持工具执行、多模态、原生 Responses 对外路由、自动历史管理或远程商业代理部署。
- 当前登录命令基于已有 Selark 用户配置；没有增加“仅 OAuth、无已有配置”的全新初始化向导。
- 官方接口处于预览期，未知新事件仍可能需要适配；错误不会自动改走其他收费来源。
