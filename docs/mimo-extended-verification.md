# MiMo 扩展场景实测

2026-10-30，官方按量 API，文本模型 `mimo-v2.6-flash` / `mimo-v2.6-pro`，
语音模型 `mimo-v2.5-tts` / `mimo-v2.5-asr`。提示、图片、音频和业务数据均为测试材料。

共发起 **296 次真实 API 请求**，另有 4 次只读模型列表查询。取得最终或完整响应体用量的
279 次请求合计 **1,997,423 tokens**（输入 1,867,456，输出 129,967）。已报告部分费用
估算 **3.0043–3.1349 元**；另 17 次未取得用量，不按零费用处理。

累计不可退回的发送前费用预留 **19.108006 / 20 元**，与实际扣费不同。API 状态为
292 次 HTTP 200、2 次主动取消时未收到响应头、2 次联网参数拒绝。267 次响应完整交付；
另有 22 次早期验收器解析中断、4 次主动取消、1 次长思考总时限退出及上述 2 次拒绝。
22 次解析中断中有 12 次已收到完整非流式用量，10 次流式用量未知。

结论：接入、长文读取、语音及代码练习可以完成；严格输出格式、停止词、强制工具控制和
复杂计算仍有需要单独处理的边界。HTTP 200、内容正确、格式合规分别统计，不能把本轮
概括为所有场景通过。脱敏明细见 [JSON 报告](mimo-extended-verification.json)。

## 场景及结果

| 场景 | 实测结果 |
| --- | --- |
| 12 类业务任务 × 两模型 | 24 次完整返回；22 次的 JSON 值正确，严格格式通过 12 次。其余包含多余围栏、去重丢失小写项、排序多出一个数字 |
| 情感标注、翻译、分页编程、文章、个人计划、产品设计 | 每模型每任务连续三轮，36 次真实历史对话；22 次通过预设检查，其余有格式、原文引文和字数问题 |
| 16 / 64 / 128 / 256 / 512 KiB 参考材料 | 10 次全部提取正确字段；只有 4 次同时满足纯 JSON 格式。最大单次报告输入 **345,801 tokens** |
| 中文长政策材料 | 两模型均找到版本 v3.2、保留 7 天、导出上限 2；Flash 用字符串表示两个数字，Pro 用数字。提示没有显式声明类型，严格类型差异不能直接归为事实错误 |
| 图表、单据 OCR、形状计数 | 六次内容值均正确，原提示模式五次多带围栏；改用 JSON Object 模式后六次全部直接解析通过 |
| 中文 / 英文语音合成与转写 | 两段合成 WAV 分别约 4.32 / 4.00 秒，两次转写均准确包含时间、地点及物品 |
| 音频理解 | 两次均识别 library / blue notebook；英文音频的回答额外带 JSON 围栏 |
| JSON Object / Schema 基础 | 两模型 × 普通/流式，共八次通过；另两次 Schema 与用户文字要求冲突时，均遵守 Schema 中的字段、类型和常量 |
| Chat Completions / Responses 函数往返 | 思考开/关、两模型共八条路线，七条执行工具并完成往返；另一次 Flash 直接答 41，未按要求调用工具 |
| 同一响应多个函数调用 | 两模型均返回两组正确加法参数 |
| Responses / Anthropic 普通与流式、Responses 推理参数 | 20 次全部完成且内容正确；档位测试使用短回复，不代表复杂推理能力排名 |
| 长篇设计、故障手册、评测方案 | 六篇完整输出，每篇 7,785–15,733 字符；汉字数 2,084–5,650，部分明显短于约 6,000 汉字的目标。结构及长度检查不等于完整语义验收 |
| 慢速消费流、主动取消、恢复 | 主轮两次慢读完整交付；四次主动取消，随后四次恢复调用正确，无生成重试 |

上述高级接口、函数、图片、语音和结构化参数直接请求 MiMo。Selark 的原有接入仍是文本
子集，本轮没有把这些高级能力加入网关。四种网关不支持的字段或无效上限均在本地拒绝。

文章场景中，Pro 有一轮只返回了写作核对说明，没有交付要求的文章；另有语气标注的证据
并非连续原文片段。这些成功传输的响应仍按具体内容要求记录失败。

## 代码和复杂计算

六份真实多轮生成的分页函数通过 **1,424 项**执行检查；另两份去重函数各通过 160 项，
合计 **1,744 项、零失败**。执行使用已有两道练习专用校验器，限制语法、内建函数、CPU、
内存及文件写入；不是对任意生成代码的安全或正确性保证。

复杂计算使用独立程序确定答案：12 项 0/1 背包的最优值为 **130**；240 行销售数据按组
汇总应为 **A=3,215、B=3,936、C=4,647**。

- 关闭思考时，Flash / Pro 的背包答案分别是 133 / 143，销售汇总也都算错。
- 8,192-token 预算下，Pro 两道题及 Flash 的销售汇总耗尽上限，没有最终正文。
  Flash 的背包响应有长篇说明，未满足只返回 JSON 的要求。
- Pro 改为 16,384-token 预算及 JSON 模式后，使用 12,719 个输出 tokens、约 131 秒，
  返回正确的 `{"maximum_value":130}`。这个对照同时改变了预算和格式参数，不能把效果
  单独归因于某一个设置。
- 固定本地计算工具在四条路线均被正确调用。Flash 两次最终 JSON 正确；Pro 两次正确
  数值后追加了 `<|im_end|>`，因此严格 JSON 检查失败。工具计算值和模型包装输出必须分开验证。

Flash 的同类 16,384-token + JSON 模式对照在 **360 秒总时限**内没有最终正文，
客户端结束等待，最终用量未知。不能据此宣称它已经消耗完整 16,384 tokens，或一定无法
在更长时间后得出答案。本轮没有自动重发该请求。

联网检索两次均返回 `400 / Param Incorrect`。第二次按官方示例显式给出
`max_keyword=1`、`limit=1`、`tool_choice=auto`，仍未成功。官方要求先开通联网插件，
但该错误不足以确认本账号是否未开通；本轮未更改账号服务，也未验证联网回答质量。
[联网服务说明](https://mimo.mi.com/docs/zh-CN/quick-start/usage-guide/text-generation/tool-calling/web-search)

## 参数边界

`stop` 共 12 次：Flash 的 ASCII `<END>` 普通/流式两次生效；Flash 的中文、emoji
及 Pro 的三种停止词共 **10 次未生效**，完整输出了停止词和之后的内容。直接 API 请求
中确实携带该参数，不能归因于网关丢字段。与[参数文档](https://mimo.mi.com/docs/zh-CN/api/chat/openai-api)
描述的停止行为存在差异。

1 / 8 / 64 / 512 / 8,192-token 上限分别测试普通和流式。没有发现报告的总输出用量
超过上限；其中 8,192-token 普通请求自行提前结束并提出替代做法，不能算作成功持续输出
到指定上限。思考内容也占输出预算，预算耗尽时可能没有最终正文。

两条 `tool_choice="none"` 对照仍返回函数调用。官方明确说明非 `auto` 值目前会被移除；
不能把兼容参数的名称当成强制执行保证。[工具选择说明](https://mimo.mi.com/docs/zh-CN/api/chat/openai-api)

Responses 的 `none` 关闭思考，其他合法档位目前没有实际强度区别；思考模式下传入的
采样参数也会被默认值覆盖。本轮只验证参数被接受及具体短任务结果。
[Responses 兼容说明](https://mimo.mi.com/docs/zh-CN/api/chat/responses)

另有两次用量细项不一致：总输出均为 8,192，但 `reasoning_tokens` 分别为 8,198 / 8,195。
保留原始值，费用按总输出计算，没有把细项重复相加。

## 并发与隔离

真实上游从发送到收到响应头的重叠峰值达到 **8**。主轮测试如下，耗时包括本地排队、
流式交付和网络；属于短时样本，不是供应商 SLA。

| 阶段 | 完整响应 / 内容正确 | P50 | P95 |
| --- | ---: | ---: | ---: |
| 1 路，2 请求 | 2 / 2 | 0.84 s | 2.45 s |
| 4 路，8 请求 | 8 / 8 | 0.83 s | 1.01 s |
| 8 路，16 请求 | 16 / 16 | 0.94 s | 2.19 s |
| 32 客户端突发中的 16 个入场请求 | 16 / 11 | 3.68 s | 8.76 s |

32 客户端突发达到 8 个执行槽、8 个排队槽，另 16 个在本地 `server_overloaded`，没有
发送上游。五个内容失败包括无理由拒答、只回单个字母、输出 `</think>` 等多余内容。
对其中四个相同正文请求直接复测，三个正确、一个仍拒答；因此至少该拒答可在绕过 Selark
时复现。换为明确的 JSON Object 模式及 `temperature=0` 后，四个对照都通过；原失败保留。

原配置哈希没有变化，测试使用临时网关、八个独立调用方、临时账本。没有修改运行服务、
OAuth、计费来源或自动重试逻辑。

## 测量修正与证据限制

首两轮共 46 次发送尝试中，验收器先后遇到可空 `tool_calls` 及函数分块中的可空参数。
已修正并增加回归；出现解析异常时停止新增请求。初次手动停止前的在途调用保留，之后
被本地守卫拦截的客户端用例不计为上游发送。后续阶段继承所有已用次数及费用预留。

这些解析中断不等同于 MiMo HTTP 失败，也不能假装早期流式调用取得了最终用量。原始
报告没有被后续成功结果覆盖。初始 Pro 回声提示末尾句点存在歧义，后续已明确禁止追加标点，
不把初始两个 `READY.` 回答作为稳健的模型缺陷结论。

主轮账本快照采集过早：执行、排队均为零时，还有四个已接纳请求在收尾，快照缺少三条
本地参数拒绝记录。**214 次真实上游尝试全部对齐，60 条成功网关用量逐条一致**，但该快照
本身未通过完整记录检查，不能称为完整账本验收。已改为等待 `admitted=0` 与待落账为零；
定向复测检查最终快照。原临时数据库已清理，未尝试补造缺失的旧快照记录。

定向复测的账本完整性与用量对照通过，最终执行、排队、已接纳和待落账均为零；恢复检查
全部为零。五个执行目录的真实发送次数均可与网关尝试及直接响应核对，原配置哈希不变，
临时配置已清理。此前主轮快照的三条缺失仅为本地拒绝，仍如实保留为检查失败。

项目全量 **617 项 pytest 通过**（62.68 秒），Ruff、格式和 diff 检查通过；有一条既有
FastAPI / Starlette 测试客户端弃用提示。真实调用没有进入 CI。

凭据复查覆盖 165 个公开文件和 609 个本轮原始证据文件，未发现
已配置凭据泄漏；公开文件另外检查了 OpenAI 项目 Key、GitHub Token 和私钥头。全部原始
证据文件确认被 Git 忽略。

## 费用和复现

费用按[官方国内按量价格](https://mimo.mi.com/docs/zh-CN/price/pay-as-you-go)估算：每百万
tokens，Flash 输入/缓存读/输出为 1 / 0.02 / 2 元，Pro 为 3 / 0.025 / 6 元；缓存写入
当时免费。ASR 按报告的音频秒数及 0.5 元/小时计算，内置音色 TTS 当时免费。联网检索
另计。缓存明细缺失时同时给出缓存价和未缓存价范围，未知消耗不按零处理。

预算来自用户陈述的 20 元，未读取控制台账单或实时余额；发送前的累计费用预留是本地
保护措施，不是实际扣费。所有阶段共用累计预算，失败、取消、缓存命中均不退回预留。

脚本：[真实测试](../scripts/verify_mimo_extended.py)、[用例与图片材料](../scripts/mimo_extended_cases.py)、
[模拟回归](../tests/test_mimo_extended_harness.py)。真实调用不加入 CI，复用会产生新费用：

```bash
PYTHONPATH=src:scripts .venv/bin/python scripts/verify_mimo_extended.py \
  --execute --work-dir .private/mimo-new-run

# 完成原轮并检查结果后，继承累计预算运行定向对照。
PYTHONPATH=src:scripts .venv/bin/python scripts/verify_mimo_extended.py \
  --execute --suite focus --prior-run .private/mimo-new-run \
  --work-dir .private/mimo-new-focus
```

只从已配置的官方 MiMo 连接读取 Key，凭据仅在内存使用。原始请求、响应、音频、生成的
长篇方案和预算证据位于 Git 忽略的 `.private/`；公开报告不包含密钥、调用方令牌或请求 ID。
