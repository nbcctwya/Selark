## 范围与执行边界

- 普通及 SSE 响应、两名隔离调用方、模型别名、文本数组、采样参数、停止序列和输出上限。
- 六类任务各两个案例、连续三轮：语气分析、翻译、编程、文章、个人计划和项目设计；
  每次续问带回此前真实回答。
- 短请求并发持续运行，输入从约 1 KiB 扩展到约 40 万 ASCII 字符；
  长文本的标记位于不同位置，检查提取值和格式。
- 缓存前缀重复、输出上限 1 / 2 / 8 / 32 / 512 / 2,048 / 8,192 Token，
  普通 CLI、流式 CLI、标准输入和别名。
- 未授权、无效字段、禁用工具调用和超大请求体的本地拦截；
  临时实例备份、完整性检查、隔离恢复、正常重启和空闲进程强制退出后的恢复。
- 有界的主动断连和总时限故障；不主动制造供应商欠费、限流或余额耗尽。

上述六类任务共 36 次、短请求矩阵完成 416 次；普通和流式长输入 30 次，
另有冒烟、别名、缓存、输出边界、停止序列、显式代码反例和四种 CLI 入口。
8,192 Token 输出完整结束，耗时约 153.11 秒。所有 531 条成功用量与账本一致。
断连和 1 秒总时限错误各保留一条记录、一次发送和未知预留，没有重发。

配置并发上限为 4，唯一生成出口每次开始至少间隔 1.25 秒（最多约 48 次/分钟）。
每次发送前原子保存并同步完整费用预留；失败、未知消耗、缓存命中和重启都不退回这笔测试预算。
上限为累计 **8 元**、1,000 次发送和两小时；不重置预算，不自动重复生成，不切换模型或来源。

临时服务总时限是 **180 秒**，最后的故障注入临时改为 1 秒；原服务默认的 120 秒没有修改。
原 WSL 服务、systemd、自启动、linger、所有原配置及账本均不参与演练。
OAuth 登录、授权、刷新和退出操作均为零。

## 计费口径

使用执行当天核对的 [MiMo 官方价格](https://mimo.mi.com/docs/zh-CN/price/pay-as-you-go)：
Flash 每百万输入 Token 1 元、缓存输入 0.02 元、输出 2 元；缓存写入当时免费。
价格快照只写入临时配置，原配置不变。

供应商不少成功响应的 `prompt_tokens_details` 是 `null`。这种情况下输入、输出和总 Token
可以准确落账，但无法知道有多少输入应享受缓存价；Selark 保留费用未知及原费用预留。
**仅把可估算记录相加会低估整轮费用。** 本报告同时给出这部分小计和全部已报告 Token
按未缓存价计算的金额；后者仍不包括最终未报告用量的主动取消尝试。

8 元测试预算按 UTF-8 长度的保守输入估算、全部输出上限和未缓存单价预留。
它是本地发送门槛，不是供应商硬扣费上限或余额查询。赠送余额来自用户陈述，
没有读取控制台实际账单和余额；[官方说明](https://mimo.mi.com/docs/zh-CN/quick-start/faq/payment)
计费可能有延迟。保留较大余量，不能把任何本地估算写成最终账单。

## 中途停止与诊断

第一次持续调用在 `matrix-0308` 遇到客户端 `RemoteProtocolError`，立即停止新增发送。
该案例没有对应的服务器日志或账本行；当时所有 **391** 条发送前预算凭据均对应
**391** 条成功账本。另三个同批本地请求被停止守卫拦截，没有传到 MiMo。
这次本地 HTTP 中断的具体原因未能证明，原整轮结果保留为未全部通过。

初版测试守卫用通用 `RequestError` 表示“尚未发送即拦截”，导致三条测试账本将其保守记为
未知消耗。这是验收器的异常分类问题；已改为明确的未发送异常并通过模拟回归验证。
三条既有记录原样保留，真实发送数以持久出口凭据为准。

审阅后显式补测从 `matrix-0312` 开始，跳过原四个失败案例；与原预算共用同一文件。
补测把本地测试客户端的空闲连接保留时间从 5 秒降至 1 秒，以避开可能的关闭边界；
这不是对原故障根因的证明，也没有加入生成重试。
一次补测启动因遗漏第二个本地测试调用方而在发送前退出，修正后重新启动，零上游消耗的证据也保留。

## 答案与供应商行为

HTTP 成功和用量一致不等于答案正确。严格检查的失败结果保留，不由网关偷偷改写。

- 部分要求纯 JSON 的回答添加 Markdown 代码围栏。只在离线分析中去掉围栏，进一步区分
  格式错误和内容错误；语气分析 A 的部分证据仍是改写或拼接，并非连续原文引用。
- 三篇文章不满足汉字数要求；四条数字排序回答次序错误，另一个回答含多余的 `</think>` 文本。
- 一次长文本提取包含正确标记，但多输出了 `TARGET_ACCESS_CODE=` 前缀。
- 分页函数的第二、三轮用截断后的页号选取内容，却把原请求页号写进返回值。
  每版 279 项执行检查中 72 项失败，包括空列表和非空越界页。
  对模型显式提供具体反例后的新回答仍有同样 72 项失败，没有把“收到修正回答”算作修复成功。
  共执行 7 个函数版本、1,927 项检查，216 项失败集中在这三版分页函数；另四版通过。
- 部分响应在发送了 `stop` 后仍返回完整停止序列。保存的请求 SHA-256 与重建出的实际发送参数
  一致，确认参数没有被 Selark 丢弃。这与 [MiMo 参数文档](https://mimo.mi.com/docs/zh-CN/api/chat/openai-api)
  描述的行为不一致，应作为上游兼容性限制；Selark 不自行裁剪回答或伪造用量。
  69 次矩阵停止序列检查有 15 次不符合预期；补测中 ASCII 字符串和数组各两次通过，
  中文停止序列 `结束` 在普通和流式各一次仍被原样输出。
- 一次短输入 SSE 的首个正文等待约 **171.46 秒**，最后成功完成。这是在临时 180 秒时限内通过，
  不能据此声称原默认 120 秒配置也能完成该请求，或将模型延迟算作本地网关耗时。

离线代码校验器同时修正了两个误判：允许普通集合的 `add`；只执行含目标函数的唯一 Python
代码块，忽略独立示例块。导入、文件操作、危险调用、顶层副作用和不允许的属性仍被拒绝，
CPU、内存和文件写入限制仍保留。这是两道练习专用校验器，不是通用代码安全沙箱。

## 复用与后续

重新使用脚本前必须核对模型、价格、余额类别、到期时间及其他程序的同时使用情况，
为**所有同时进行的调用**保留余量；不要沿用本次余额数字。
`SELARK_DATA_DIR` 环境覆盖会破坏隔离假设，脚本因此拒绝运行；不要把临时目录设为原配置目录。

```bash
# 示例数字必须替换为当时已核对的余额和保守预算；会真实扣费。
.venv/bin/python scripts/verify_mimo_credit.py --execute \
  --work-dir /tmp/selark-mimo-NEW-PRIVATE-RUN \
  --python /absolute/pipx/venvs/selark/bin/python \
  --verified-gift-cny GIFT_AMOUNT --max-reserve-cny SAFE_CAP --matrix-calls 420
```

脚本遇到异常会停止；先保全账本与预算，再分析是否需要新的独立案例。
补测的审核文件只允许此前发送全部已有成功记录、预算未变且不重复失败生成的情况。
临时配置和备份含凭据，导出脱敏结果、确认临时服务停止后应一并清理。

下一阶段优先考虑按供应商记录参数实际生效情况、缺少缓存计数时的费用区间展示，
以及更完整的本地 HTTP 连接诊断。供应商 429、5xx、异常 SSE、存储故障和 OAuth 边界继续采用
现有模拟注入；本轮没有用真实收费请求强行触发它们，也没有演练 WSL 重启或自启动。
